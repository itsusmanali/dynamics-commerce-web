# Dynamics modules

Each folder is one portable Next.js + Gutenberg module. The JSON definition is the authoring contract shared by both applications.

## Module files

- `<name>.definition.json`: friendly name, categorization, config controls, localized resources and defaults.
- `<name>.data.ts`: cached/server-side API and WordPress data access.
- `<name>.props.autogenerated.ts`: generated TypeScript; never edit manually.
- `<name>.tsx`: orchestration and business logic.
- `<name>.view.tsx`: render-only React view.
- `<name>.module.scss`: optional scoped SCSS. Tailwind classes are supported in every TSX file.

Run `npm run modules:generate` after adding or changing a definition. It generates props, the static Next.js module registry, and the fallback WordPress `modules-manifest.json`. Dev and production builds run it automatically. Once Connector 2.1 is installed, WordPress automatically synchronizes the deployed manifest from Vercel; definition changes do not require another plugin upload.

## Supported authoring fields

`string`, `text`, `number`, `boolean`, `color`, `select`, `url`, and `image`. Fields can be grouped and can include help text, defaults, options and required markers.

Resources are stored per locale (`en`, `fr`, `fr-ca`, etc.). Next.js resolves an exact locale, then the base language, then English, then the definition default.

## WordPress composition

- Insert any Dynamics module alongside native Gutenberg blocks.
- Create reusable compositions under **Module Fragments**.
- Insert a Module Fragment block anywhere in a page or template.
- Create shared compositions under **Page Templates**, then attach one in the page sidebar.
- Select global header/footer fragments under **Settings → Headless Frontend**.

Template modules render before page modules. Native Gutenberg blocks retain their position between Dynamics modules.

## Template extensions

Templates support a wrapper class, structured custom meta tags and allowlisted script IDs. Add reviewed scripts to `templates/script-registry.ts`. WordPress cannot store or execute arbitrary frontend JavaScript.

## Adding a module

1. Copy `modules/header` to `modules/<name>` and rename its files.
2. Set the same lowercase slug in the folder and definition `name`.
3. Define config fields and resources.
4. Run `npm run modules:generate`.
5. Build and upload the regenerated connector ZIP.
